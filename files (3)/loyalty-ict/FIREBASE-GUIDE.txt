LOYALTY ICT SOLUTIONS — FROM DEMO TO REAL BUSINESS
========================================================

WHAT YOU HAVE NOW (be clear on this)
------------------------------------
This is a fully working DEMO. Every feature runs, but all data
(products, orders, bookings) is saved in the browser it's opened
in, using localStorage. That means:

  - It works perfectly for one person on one device.
  - It is great for showing customers and testing your flow.
  - It is NOT yet multi-user. If a customer orders on their phone,
    YOU won't see that order on your admin phone. Each device has
    its own separate copy of the data.
  - The M-Pesa payment is a realistic SIMULATION, not real money.
  - The admin password (loyalty2025) lives in the code, so anyone
    who reads the file can find it. Fine for demo, NOT for real use.

To run a real business, you wire in a backend. You already chose
the right one: Firebase. Here's the honest map.


STEP 1 — HOST IT (do this today, it's free)
-------------------------------------------
1. Go to app.netlify.com/drop
2. Drag the WHOLE folder (index.html, manifest.json, sw.js,
   icon-192.png, icon-512.png) onto the page.
3. You get a live https link. Open it on your phone.
4. On Android Chrome: menu -> "Add to Home screen" -> it installs
   like an app. On iPhone Safari: Share -> "Add to Home Screen".

At this stage it's live and installable, still demo data.


STEP 2 — CREATE FIREBASE (free tier is enough to start)
-------------------------------------------------------
1. Go to console.firebase.google.com -> Add project -> name it
   "loyalty-ict".
2. Add a Web App. Firebase gives you a config block like:
     const firebaseConfig = { apiKey:"...", projectId:"...", ... }
3. Turn on these three products in the console:
     - Authentication  (for secure admin/staff login)
     - Firestore Database  (stores products, orders, bookings)
     - Storage  (stores product images properly, instead of
       squeezing them into the browser)


STEP 3 — REPLACE THE DATA LAYER
-------------------------------
In index.html find the block marked "DATA LAYER (demo = localStorage)".
Right now it reads/writes localStorage. You replace those reads and
writes with Firestore calls. The rest of the app barely changes,
because everything already goes through DB.get() / DB.set().

Add before </body>:
  <script type="module">
    import { initializeApp } from "https://www.gstatic.com/firebasejs/10.12.0/firebase-app.js";
    import { getFirestore, collection, getDocs, addDoc, doc,
             updateDoc, deleteDoc } from "https://www.gstatic.com/firebasejs/10.12.0/firebase-firestore.js";
    const app = initializeApp(firebaseConfig);
    const db  = getFirestore(app);
    // then rewrite product/order/booking reads & writes to use
    // getDocs(collection(db,'products')), addDoc(...), etc.
  </script>

Collections to create: products, orders, bookings.


STEP 4 — REAL SECURITY (this is your selling point as a security guy)
---------------------------------------------------------------------
1. Admin login -> use Firebase Authentication (email + password
   for you and each staff member). Delete the hard-coded password.
2. Lock the database with Firestore Security Rules so that:
     - Anyone can READ products (the shop is public).
     - Only logged-in ADMINS can create/edit/delete products.
     - Customers can CREATE their own order, but only admins can
       read all orders or change order status.
   Example rule idea:
     match /products/{id} {
       allow read: if true;
       allow write: if request.auth != null && isAdmin();
     }
     match /orders/{id} {
       allow create: if true;
       allow read, update: if request.auth != null && isAdmin();
     }
3. Never put secret keys (like the M-Pesa Daraja secret) in this
   file. They go in a serverless function (Netlify Functions or
   Firebase Cloud Functions), never in the browser.


STEP 5 — REAL M-PESA PAYMENTS
-----------------------------
1. Register for Safaricom Daraja API (developer.safaricom.co.ke).
2. Get a Paybill or Till (Buy Goods) number for your business.
3. The STK Push MUST be triggered from a backend function (Netlify
   Function or Firebase Cloud Function), because it needs your
   secret keys. The browser calls your function; your function
   calls Safaricom. This keeps your keys safe.
4. Safaricom sends a callback confirming payment -> your function
   marks the order "paid" in Firestore.

You already built an M-Pesa STK Push in sandbox before, so this
step is familiar territory.


STEP 6 — REGISTER THE COMPANY
-----------------------------
Business name / company registration in Kenya is done via the
eCitizen portal (BRS - Business Registration Service). Decide
between a sole proprietorship (simplest, cheapest) and a limited
company (more protection, needed for bigger contracts). Get:
  - Business name registration
  - KRA PIN for the business
  - A business M-Pesa Till/Paybill in the company name

Put the registration number and physical address in the footer of
the site once you have them. THAT is what makes a store look real
and trustworthy — not any design trick.
